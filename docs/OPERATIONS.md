# NAMAE 運用手順

## ブランチと公開

- `develop`: 日常の開発と検証。変更はこのブランチへpushする。
- `main`: 本番公開候補。`develop`からPull Requestを作り、CI成功とデータ品質レポートの確認後にマージする。
- ホスティング側では`main`だけを本番へ公開する。プレビュー公開はPull Request単位で行う。

本番ビルドにはNode.js 24を使用する。`NEXT_PUBLIC_SITE_URL`には本番URLを設定する。障害収集先を使う場合だけ`NEXT_PUBLIC_MONITORING_ENDPOINT`を設定する。

## データ更新

全搭載国を再照合する場合は `npm run data:refresh:all-countries` を使用します。WikidataのP735（名）・P734（姓）と、公開人物のP27（国籍）または出生地のP17/P131を明示的な国別根拠として使います。P21の明示記録がない下の名前に性別を推測で追加しません。公人の使用例は一般人口を代表しないため、人口順位や人数を付けず辞書に保存します。順位が存在する場合は順位付きデータを優先します。各国の原クエリ・取得日時・名前項目IDを圧縮保存し、問い合わせの失敗や未追加区分も `reports/all-country-expansion.json` に記録します。スロベニアは全6表（名字4分割）を取得し、最新年の公開住民人数から順位を再集計します。

国別取得の途中で停止した場合は `npm run data:collect:all-countries` で取得済みクエリを再利用して再開できます。表記の照合は `node scripts/import-wikidata-country-names.mjs` で再開します。キャッシュは完了した応答だけを採用し、HTTP 200でも途中で切れた応答は不採用とします。ラベルは圧縮キャッシュから再利用し、APIへの問い合わせ間隔と再試行待機を設けます。漢字・ハングルの1文字名は有効な名前として扱い、英字1文字のイニシャルと区別します。

イギリスの名字は `npm run data:refresh:uk-surnames` でONSの1996–2025年出生登録原本から再集計します。英国全域の現在人口ではなく、イングランド／ウェールズの出生姓の公開件数累計です。各年2件以下の非公開人数は補間しません。`data:refresh:europe` にもこの取り込みを含めています。

ベルギー（男女名・名字）、ノルウェー（男女名・名字）、スイス（名字）、オーストリア（男女名）は `npm run data:refresh:europe` で取得・再集計します。取得済み原本をキャッシュするため、通常のビルドでは再取得しません。ノルウェーの人数非公開の保護姓は順位なし辞書に保存します。ベルギー・スイスの順位は自治体の公開人数を合算した順位であり、非公開セルを補った全国順位ではありません。ベルギー原本はWindows-1252で読み、同一自治体・同一名字の重複行は最大値を採用して二重加算を防ぎます。オーストリアは出生年別件数を合算します。取得結果は `reports/europe-expansion.json` に記録します。

全搭載国の拡張は `data:refresh:national-expanded`（イタリア・韓国）、`data:refresh:chile`、`data:refresh:nordic`（フェロー諸島・グリーンランド）、`data:refresh:global-references` の順で行います。全国統計の順位と、国別辞書の順位なし候補は別々に保存します。`data:expansion-report` で全搭載国の追加数・残る不足・出典を記録してください。辞書の国は原本の国指定のみを使い、言語や似た名前を根拠に他国へコピーしません。公開データのマニフェストはschemaVersion 4で、辞書候補も1,000件ごとに分割配信します。一般ビルドではネットワーク取得を行いません。

カナダの下の名前は `npm run data:refresh:canada` で同梱原本から再集計します。最新原本を取得する場合は `npm run data:refresh:canada -- --refresh` を使用します。Statistics Canadaの公開人数を年ごとに合算した順位で、非公開人数は含みません。カナダの名字にはこの出生データを流用しません。

1. 取得スクリプトを実行し、`data-sources/`の原本と`src/data/`の整形結果を更新する。
2. `npm run data:sanitize`を実行する。
3. `npm run data:check`を実行し、`reports/data-quality.md`の件数差分、文字体系、警告を確認する。
4. 意図した変更なら`npm run data:accept`で品質基準を更新する。
5. `npm run data:build`でSQLiteとハッシュ付き公開JSONを生成する。
6. `npm test && npm run lint && npm run build && npm run test:browser`を実行する。
7. 原本、整形データ、品質基準、公開JSONを同じコミットに含める。SQLiteはOS差によるバイナリ差分を避けるためGit管理せず、各ビルドで再生成する。

10%以上の件数減少、文字体系の混入、空データ、国・種別の不一致は品質検査で停止する。公開JSONは一時ディレクトリで生成してから入れ替えるため、生成途中のファイルは公開対象にならない。

## 出典とライセンス

`data-sources/SOURCES.json`を出典台帳とする。新しい出典にはURL、対象データ、ライセンスURL、帰属表示、再配布確認状態を登録する。

`npm run licenses:check`は確認中の出典がある間は失敗する。`main`へのpushでも同じ検査を実行する。提供元の明示的な許可または専門家による確認を得た後だけ、`redistributionStatus`を`permitted`へ変更する。

## 登録数が少ない国の優先拡張

`npm run data:priority-report`で、全搭載国を名前（男女合計）・名字それぞれの登録数が少ない順に集計する。綴りを正規化して重複を除き、人口順位と辞書件数は同一視しない。初回の下位30か国ずつの和集合と変更前の件数を`reports/priority-country-expansion-before.json`へ保存し、取得再開時も同じ対象を維持する。結果は`reports/priority-country-expansion.md`とJSON版に出力する。

`npm run data:refresh:priority`は対象を登録数が少ない順に取得する。WIPO WGND 2.0の国コード付き原本（CC0、file ID 4750348）と、Wikidataの人間・名/姓・性別・国籍/出生地/居住地が明示された構造化記録を使う。WGNDの言語拡張版、国コードなし版、音による国籍・性別推測は使用しない。WGNDの`wgt`は出典の重みであり、人数・順位に変換しない。居住記録には外国籍・歴史上の居住者も含まれるため、出典注記と各候補の関連種別を保持する。公人の辞書を一般人口のランキングとして表示しない。

原本は圧縮して保存し、WGNDはSHA-256を照合する。国別辞書の`--priority`更新では対象外の登録と出典を保持する。取り込み後は`npm run build`でSQLiteと公開JSONを再生成し、`npm test`とブラウザーテストを実行する。順位付きデータが追加されない国でも、順位のない実在名の候補を増やせる。新規候補を取得できない国はレポートに理由を残す。

## 人数に基づく資料内参考順位

`npm run data:refresh:observed-ranks`で、名前・名字それぞれの登録数が少ない30か国の和集合を集計する。初回の対象と件数は`reports/observed-ranking-expansion-before.json`へ保存し、結果は`reports/observed-ranking-expansion.md`に出力する。国籍・出生地・居住地が明示され、名/姓エンティティが明示されたWikidataの人間レコードだけを対象とする。人物IDを集合にして重複を除き、同じ綴りの異なる名エンティティも人物で重複除外する。男女別・名字別に実人数を降順で集計し、同人数は1,1,3方式で同順位とする。一人が複数の名を持つ場合は各名に1人として数え、全体人数は人物IDの和集合とする。

`ReferenceNameRecord.evidenceRank`は全国順位の`rank`と別フィールドで、`observedPeople`・`totalPeople`・`totalNames`・同率数・取得日・出典IDを保持する。集計クエリはメタデータの`evidenceRanking.sourceUrl`から再現できる。SQLiteと公開JSONにもこの区別を保持する。配信チャンクは根拠のある参考順位付き候補を独立させ、同じ全国順位を取得できないときだけ優先して読み込む。根拠のないWIPO等の辞書項目に架空の順位を付けない。

画面と保存画像は「資料内参考順位」と表示し、全国の人気順位・日本との同順位を示さない。公開人物という標本の偏り、歴史上・外国籍の居住者も含むこと、同率順位の扱いを根拠表示に含める。全国の統計と資料内順位を混ぜて順位対応の成功数や網羅率として数えない。取り込み後は通常の`npm run build`で全配信用データを再生成する。

日本の名前の出力では、現行データに同順位がない場合、保存済みのベビーカレンダー年度別公開順位から同順位を探す。該当順位を確認できる最も新しい年度を採用し、カード・共有画像にもその調査年を表示する。例：アルゼンチンのLeoが76位なら、日本は2024年76位の「だん」。2025年75位の「けいと」の順位を76位へ変更しない。`scripts/japanese-rank-alternatives.mjs` が公開原本から出力専用データを生成し、配信manifestの `rankAlternatives` に登録する。入力名の検索用ランキングはこの出力専用データで上書きしない。公開資料にも同順位がない場合は、既存の参考候補・近い順位という表示を維持し、同順位を作り出さない。

## 監視

初回39か国以外の全対応国（中国・台湾・東南アジア・欧州・アフリカなど）の資料内参考順位は `node scripts/refresh-world-rankings.mjs` で再取り込みできる。対象は `scripts/world-ranking-countries.mjs` に明記。初回の変更前件数は `reports/world-ranking-expansion-before.json` に保存し、前後比較を `reports/world-ranking-expansion.md` に出力する。従来39か国の出典登録と原本は維持する。中国は漢字表記を優先し、同じローマ字になる別の姓を漢字別に集計する。

この追加集計は主に国籍が明示された公開人物が対象で、プエルトリコ・フェロー諸島は出生地・居住地の明示記録も含める。デンマークはデンマーク王国の国籍記録も集計する。全国人口の人気順位ではない。取得結果を途中で打ち切る件数制限は設けず、完全なJSON応答だけを保存する。取得エラーが残った場合は後続の反映処理を中止する。取り込み後は `npm run build` で配信用データを再生成する。

GitHubリポジトリのActions variablesに`PRODUCTION_URL`を登録すると、`.github/workflows/monitor.yml`が毎時トップページ、データマニフェスト、全データファイルの到達性を確認する。失敗通知はGitHub Actionsの通知設定で受け取る。

クライアント障害収集を使う場合、同じオリジンまたは信頼できる収集先を`NEXT_PUBLIC_MONITORING_ENDPOINT`へ設定する。送信するのは障害コード、ページパス、発生時刻、データ種別だけで、入力名・読み・結果・例外本文・スタックは含めない。

## 障害対応とロールバック

1. GitHub Actionsのhealth checkとホスティングの状態を確認する。
2. データ障害なら`public/data/manifest.json`の`dataVersion`を記録する。
3. 直前の正常な本番デプロイへホスティング側でロールバックする。
4. Gitでは原因コミットを`git revert`し、Pull Request経由で`main`へ反映する。
5. データ障害は品質検査へ再現ケースを追加してから再公開する。

入力内容はログへ記録しない。障害の記録にはデータバージョン、発生時刻、影響ページ、HTTP状態、復旧コミットだけを残す。

## バックアップ

Gitのタグと本番デプロイを復旧点とする。本番公開ごとに`release-YYYY-MM-DD-N`形式のタグを作成する。SQLiteと公開JSONはソースから再生成できるため、原本と出典台帳を必ず同じリポジトリで保持する。
